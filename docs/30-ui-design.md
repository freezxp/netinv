# 30 — UI Design (every page)

**Status:** review · **Depends on:** 02, 09, 14 · Components/stack: doc 14

The kickoff brief listed pages from a virtualization-flavored template; mapped to this product: *Asset Detail / Host Detail* → **Device Detail** (one page; future host monitoring reuses it), *Storage* → deferred with category 8/10 (doc 29), *Network* → **Topology & Weathermaps**. All listed concerns are covered below.

## 0. Shell, navigation & design language

- **Shell:** left sidebar (collapsible to icons): Dashboard · Weathermaps · Inventory · Alerts · Topology · Platform · Audit · Settings · Users — items RBAC-filtered (`<Can>`, doc 14). Topbar: global search (⌘K — devices/interfaces/maps/pages), site filter (persistent, scopes every page), alert bell with severity badge, user menu (profile, theme, logout).
- **Design language:** dense-but-calm ops UI. Tokens: 4 px spacing grid; `Inter` UI font, `JetBrains Mono` for IPs/serials/OIDs. **Status colors are the product's grammar** and identical everywhere (badges, map nodes, heatmap, charts): up/ok `green-500`, warning `amber-500`, critical/down `red-500`, unreachable `slate-400`, disabled/unknown `slate-600 outline`, info `sky-500`. Severity always paired with an icon/shape (color-blind safe); WCAG AA contrast in both themes.
- **Dark mode** (default for NOC): CSS-variable tokens flip via `class="dark"`; charts and weathermap consume the same variables (no hardcoded chart palettes); user preference `system|light|dark` per FR-SET-03. Light theme for office/report use.
- **Responsive** (NFR-60): breakpoints ≥1280 full grid · 768–1280 dashboard collapses to 2-col, tables shed secondary columns · <768 the sidebar leaves the layout entirely and becomes an overlay drawer behind a topbar hamburger — at 208px wide it otherwise took over half a 393px screen — closing on navigation and on backdrop tap; data tables keep a min-width and scroll inside their own card rather than squeezing columns to illegibility; dialogs size to the viewport instead of a fixed width; and the view is read-mostly (status row, alert list, ack actions; weathermap view-only pan/zoom; editor desktop-only). NOC-wall mode: `/wall` route — dashboard variant with no chrome, larger type, auto-cycling optional.
- **The dashboard is assembled from a per-user layout, not a fixed sequence** (`features/dashboard/layout.ts`, stored via `GET/PUT /users/me/preferences`). A **Customise** button opens an editor to add, remove, reorder and widen panels; the default layout is exactly what the dashboard showed before it became customisable, so someone who never opens the editor sees no change. Panel kinds: status strip, active alerts, bandwidth in/out, latency, Top-N, heatmap, watchlist, plus three that carry their own configuration —
  - **Weathermap**, embedding a published map read-only with pan and zoom disabled (a map that drifts under a passing cursor is worse than useless on a wall display), with a link through to the full view. Drafts render as unavailable rather than blank.
  - **Custom metric**, choosing any series the deployment publishes (`GET /metrics/names`, filtered to `netinv_*` so VictoriaMetrics' own internals stay out), with an optional label filter, a group-by, and a per-second rate toggle for counters. The expression is assembled from those fields rather than typed: a raw MetricsQL box is powerful and unusable, and this covers what a dashboard needs.
  - **Top flow**, a ranked table of talkers, conversations or applications (doc 34) — fleet-wide across every exporter by default, or narrowed to one, with a row count. Repeatable, because the three dimensions answer different questions and wanting talkers beside applications is the normal case. Deliberately a table rather than a chart: the dashboard question is "what is consuming the network", which is a ranking, and five overlapping lines answer it worse in the same space — the device Flow tab already carries the time dimension. The exporter picker lists addresses actually seen rather than accepting free text, so a typo cannot masquerade as an empty panel, and when nothing is exporting it says so in the editor instead of silently adding a panel that will never fill.
  Reordering uses buttons, not drag-and-drop — drag is nicer with a mouse and unusable at the phone width NFR-60 requires, and a NOC dashboard is arranged once then left alone. A stored layout referencing panel kinds that no longer exist falls back to the default whole, and **Reset to default** is always available, so a bad layout is never a trap.

- **Bandwidth panels are per direction, not combined.** Inbound and outbound each get their own per-site chart, side by side, with latency spanning the row beneath. Two charts rather than one with ten series: a half-width chart carrying in *and* out for every site is unreadable, and the alternative — one expression combining both — needs `label_set` to survive, because multiplying by 8 strips `__name__` and leaves both sides with the identical label set for MetricsQL's `or` to collapse. That bug has landed three times in this codebase; two independent queries cannot reproduce it. Direction matters operationally: a site is routinely comfortable inbound and saturated outbound, and asymmetric links make the two numbers unrelated.

- **Polling interval (FR-COLL-04, FR-SET-01):** a fleet-wide cadence selector on `/platform` → Pollers — 1, 5, 10 or 15 minutes — writing the default profile's traffic interval and re-scheduling every device that uses it. A fixed set rather than a free number: the interval interacts with `rate()` lookbacks, chart resolution and storage growth, and each option has been checked against all three. Health follows traffic when traffic overtakes it, so a fleet asked to poll every fifteen minutes does not quietly keep reading CPU every five. **ICMP is deliberately left at 30 s** — availability is the fastest signal that something has gone down, and slowing it would delay every outage alert by the same amount. Changes are audited, since a cadence change explains both a step in storage growth and a change in graph resolution.

- **Graph time range (FR-DASH-09):** one shared selector applying to every time-series chart in the portal, persisted in `localStorage` across pages and reloads. An operator holding one question ("what did last week look like?") should not have to re-answer it on each page, and previously could not: the dashboard was fixed at 24h, a device's traffic chart at 6h and its health charts at 24h, with nothing on screen saying which. Every chart card now names the window it shows.
  - **Presets are Cacti's graph timespans, in Cacti's order and wording** — Half Hour, Hour, 2/4/6/12 Hours, Day, 2/3/4 Days, Week, 2 Weeks, Month, 2/3/4/6 Months, Year, 2 Years — defaulting to Cacti's own "Last Day". NetInv is a successor to Cacti + Weathermap and its likely operators have twenty years of muscle memory for that list; a shorter invented one buys nothing and costs familiarity. Nineteen entries is more than a button row can carry, so the control is a dropdown, which is also what Cacti uses.
  - **Placement:** with the charts, not at the top of the page, because the dashboard's status strip and the availability tiles are server-computed over fixed windows and are deliberately unaffected. On device detail it is hidden on History and Alerts, whose tables would otherwise appear to be filtered by it. The weathermap viewer carries one too: its link hover graph follows the same range, but that card is a transient overlay with pointer events disabled, so without a control on the page chrome the map would be the one place showing a window you cannot change.
  - **Resolution and rate windows scale with the span** (`src/api/timerange.ts`). Step is chosen to land each span near 150–400 points and never goes below the 60 s poll interval, which is the finest real resolution there is. `rate()` lookbacks derive from the step rather than a fixed `[5m]`: at a one-day step a five-minute lookback measures five minutes out of twenty-four hours and reports it as the whole day, which renders long spans as noise with wrong peaks. The lookback never falls below four poll intervals, so a rate stays defined when a device is polled slowly or drops a sample.
  - **Consequence worth knowing:** wide spans show sustained averages, so a 1-week peak reads lower than the same traffic at 1 hour. That is correct for capacity work; percentile views are the refinement, not a narrower fixed window.
  - **Retention:** presets longer than the deployment keeps are shown but **disabled**, grouped under "Beyond retention". The ceiling comes from `GET /metrics/limits` rather than a build-time constant, because the API *rejects* an over-long range with 422 instead of clamping it — a picker that guesses wrong offers presets that error rather than presets that return short graphs, which is exactly what shipping the Cacti list against a 90-day ceiling did. With the default retention of 2 y nothing is disabled; the group appears only where an operator has lowered `NETINV_VM_RETENTION`, and raising it re-enables them with no frontend change. Disabled-but-visible beats hidden: an operator wondering where "Last Year" went is worse off than one who can see it and why.
  - **Not implemented from FR-DASH-09:** a custom start/end range. It needs URL state first, so that a window can be shared in a link; the presets deliberately do not touch the URL.

- **Footer:** a single line under the content on every page — `NetInv <version>` and a link to the source repository (`github.com/freezxp/netinv`). The version is stamped into the bundle by Vite's `define` at build time rather than fetched from the API, so it describes the JavaScript the browser is actually running instead of the API it happens to be talking to; `quickstart.sh` passes `git describe --tags --always --dirty`, so a deployment running ahead of a release says `v1.0.0-9-g0197178` rather than claiming to be `v1.0.0`, and `package.json` is the fallback when built outside a checkout. It sits **inside the scrolling content column**, not pinned to the viewport: a NOC screen cannot spare a permanent strip, and this is a reference detail wanted a few times a year, when someone reports a bug and has to say what they are running. The same footer appears on `/login` — the one page reachable without credentials, which makes it where you look to identify a deployment you cannot yet sign in to. The repository link carries `rel="noopener noreferrer"`; without `noreferrer` an authenticated page hands the deployment's hostname to GitHub in the `Referer`.

- **Global patterns:** every list = FilterBar (chips + saved filters + URL state) + virtualized DataTable (sortable, column picker, export menu) + row → detail drawer or page. Every timestamp shows relative + absolute on hover, user-timezone display, UTC storage. Every panel shows data-age when stale (doc 23 §6). Empty states teach ("No devices yet — Add device or Import CSV"). Destructive actions: typed-confirmation modal. All data via TanStack Query hooks with skeleton loaders; errors per doc 23 §6.

## 3. Weathermaps `/maps`, `/maps/:id`, `/maps/:id/edit` (flagship)

**Parallel links.** More than one link between the same pair of nodes is a real thing to draw — a second WAN circuit, a LAG member, a second tunnel — and the definition always allowed it, since links carry their own ids and nothing dedupes them. What it did not allow was *seeing* it: coincident links drew the same path, so three rendered as one line and only the topmost could be clicked. Links sharing both endpoints **and** both handles are now laid out in lanes, offset perpendicular to the line and spread symmetrically about it, so a lone link keeps exactly the centre line it always had. The bundle is direction-agnostic — A→B and B→A between the same sides are the same geometry — and handles are part of the key, because links attached to different sides of a node already diverge and should be left alone.

**Editing links.** A selected link's panel offers **Remove link**, and the Delete key removes it too. Previously neither existed: the only way to drop a link was to delete one of the nodes it joined, which took every other link on that node with it — rebuilding a node to remove one link is not a workflow. The keyboard path needed edge selection to be driven by the editor's own state, because `toFlow` rebuilds every edge object from the definition on each render and wiped React Flow's internal selection flag, leaving the key with nothing to act on.

- **List:** card grid with live mini-thumbnails, name, node/link counts, worst-state ring, updated-by/when; New Map / Import JSON.
- **Viewer:** full-bleed canvas; pan/zoom (wheel/pinch), fit/100% controls; legend (utilization scale + node states) collapsible; link hover → tooltip (both directions with which one the band is coloured for, %, errors, speed; both are also on the canvas) with 1h mini-sparkline; link click → interface detail; node click → device peek drawer (status, top alerts, CPU/mem) with "open device". Auto-refresh ≤30 s (FR-MAP-05); presence-aware (doc 05 §7). Fullscreen/wall mode.
- **Editor** (Operator+): left palette (Device node — search picker w/ status preview; Site node; Cloud node; Text label), canvas with snap-grid + alignment guides, right inspector (selected node/link properties: label mode, link endpoints A/B pickers as device→interface cascading selects, bandwidth override, width, curve style). Toolbar: undo/redo, draft-saved indicator (autosave 2 s), **Suggestions** panel (LLDP adjacencies not yet drawn → one-click add, FR-MAP-06), validate (broken bindings listed), Publish (diff summary vs published), Export JSON. Unsaved-draft banner on the viewer if a newer draft exists.
- Link rendering spec: each link = two half-arrows (A→B, B→A) colored independently by that direction's utilization on the classic Cacti scale (options.util_scale); grey dashed = endpoint missing/removed (doc 11 §4); black = no data.

## 4. Inventory `/inventory` (+ groups)

FilterBar: search (name/IP/serial/model — FR-DEV-03), facets vendor/site/status/group/firmware/tag; grouping selector (by site → collapsible sections). Table columns (picker-managed): status dot, **name — the device's own sysName leads, with the operator's label kept beside it when the two differ (neither is lost; sync never overwrites operator-owned fields, doc 11 §3)**, mgmt IP, site, model, **live CPU / memory / hottest-sensor temperature** (one shared `/dashboard/device-health` payload for the page, threshold-tinted, dash when the connector exposes no health), tags. Serial, OS, interface counts and last-sync are available via the column picker. Each row carries a **Retire** action (soft: stops polling, hides from the default list, keeps history, restorable); filtering by status `retired` reveals retired devices, where an Admin gets **Restore** and **Delete** — the latter behind a typed-name confirmation that states exactly what is destroyed (interfaces, schedules, topology links, change history) and what is not (metrics expire by retention; audit records persist). Each row also opens an **OID browser** — a live SNMP walk of the device with type-aware rendering (binary as hex, IPs and TimeTicks decoded), preset roots (mib-2, interfaces, host-resources, UCD-SNMP, LLDP, vendor tree), free-text filter and copy-all. It answers both "what does this platform actually support?" when writing a connector and "why is this metric empty?" in the field. Bulk-select → assign group/profile, enable/disable, export. Export menu: CSV/XLSX now (PDF P1) — exports the filter result, async job with toast → download (doc 09 §13). Buttons: Add Device (modal wizard: identity → site/connector/credential [test button inline] → profile → confirm), Import CSV (upload → column mapping → per-row validation report → commit). Device Groups tab: group CRUD, membership management. Interfaces tab: cross-device interface search ("find alias 'uplink'").

## 5. Device Detail `/devices/:id` (asset + host detail)

Header: status dot + name + IP + vendor/model chips, site, uptime, active-alert pills; actions: Sync now, Enable/Disable, Edit, Retire (Admin: Purge). Tabs:

- **Overview:** identity card (sysName/Descr/Location/Contact, serial, firmware, connector+version, credential name, profile) · health tiles (CPU, memory, worst temp, fan/PSU status, poll success 24h) each with 24 h sparkline · mini-topology (this device + LLDP neighbors, click-through) · active alerts list.
- **Interfaces:** table (status, name, alias, speed, utilization in/out bars, errors/discards 24h, optic dBm where present, monitor toggle); row expand → inline traffic graph over the selected range; row click → **Interface detail** `/devices/:id/interfaces/:ifId`: full graph set (traffic, packets by type, errors/discards, utilization, optics) with range picker, link partner (LLDP), maps-containing-this-interface list.
- **Health:** stat tiles (CPU %, memory %, 1-minute load, hottest sensor, memory used/total) with warn/critical tinting, over a graph set: CPU utilization, memory utilization, temperature per named sensor, and load average (1/5/15m) — all over the selected range (§0). Sources are connector-dependent (vendor MIBs on Cisco/Juniper/Huawei; UCD-SNMP + LM-SENSORS on net-snmp devices such as Ubiquiti UniFi gateways), so the tab states plainly when a device's connector exposes no health rather than rendering empty charts. Fan RPM, PSU state timeline, optics per port and the component inventory table extend this tab as those collectors land.
- **Availability:** RTT min/avg/max + jitter + loss graphs over the selected range, availability % tiles (24h/7d/30d — fixed windows, independent of the range selector), poll success/timeout timeline.
- **Flow:** what the traffic on this device *consisted of*, where the Interfaces tab says only how much there was (doc 34). A dimension switch — talkers / conversations / applications — over a ranked table (total bytes, share, average rate across the selected range) and a chart of the heaviest five. An interface selector narrows it to one ifIndex; the default sums across all of them. A `sampled` badge appears when the exporter declared sampling, because those figures are extrapolations and the interface counters remain the authority for volume.
  It also carries the **NetFlow v5 setup guide** — the four traps that account for most first attempts (version 5 must be set explicitly; active timeout down from its 30-minute default; per-interface ingress, not just global; v5 is IPv4-only), per-vendor snippets with the collector address substituted in and a copy button, and the checks to run in the order that rules out the previous one. Expanded when the tab is empty, collapsed behind a disclosure once flow is arriving, because configuring the *second* exporter is the normal next step after the first works. The address offered is the host the browser reached NetInv on, except that a loopback address is replaced by an obvious placeholder: pasted into a router, `localhost` points the exporter at itself and produces a correct-looking configuration that sends flow nowhere.
  Unlike Wireless, the tab is **always present**, not conditional on data existing. Wireless data appears because of what a device *is*; flow appears because of what an operator *configured*, so hiding the tab until data arrives would hide it exactly when someone is trying to find out why none has. When empty it carries the diagnosis instead of a shrug, distinguishing three cases an operator otherwise cannot tell apart: nothing arriving anywhere, nothing arriving from this device, and — the common one — flow arriving from an address other than the device's management IP, since attribution keys on the datagram's source and a router exporting from a loopback will not match. The last case names the addresses actually being received from.
- **History:** asset-history timeline (FR-DEV-07) — grouped by sync run: field chips old→new, hardware-replaced highlighted; filter by object/field; link to the sync run.
- **Alerts:** instance history for this device with state timelines.
- **Sync:** sync-run list (trigger, duration, outcome, changes), on-demand sync button, next scheduled.

## 7. Topology `/topology`

## 8. Platform `/platform` (management)

Tabs: **Sites** (tree region→DC, device/poller counts, CRUD) · **Pollers** (fleet table: name, site, status, heartbeat age, version, polls/s, buffer depth, queue lag; enroll flow: generate token modal with copy-once token + install one-liner; approve pending; disable/re-enroll) · **Connectors** (catalog cards: vendor logo, id, version, capability badges (traffic/health/topology/…), verified-models list, device count) · **Credentials** (Admin-only: table name/kind/protocols/ref-count; create/rotate modal with write-only secret fields + test-against-device; delete blocked while referenced with device list) · **Discovery** (FR-SYNC-04): define a scan (CIDR + site + candidate credential chips), run it on demand, and work the results queue — each find shows its IP, sysDescr, auto-matched connector, and whether it is already managed; approve (with an editable name, defaulting to sysName) onboards it as a tagged `discovered` device, or ignore it · **Polling profiles** (interval matrix editor with per-family toggles, device count, min-interval guards).

## 12. System Health `/platform/health` (Admin — doc 22 §5)

Pipeline throughput diagram with live numbers (jobs → polls → samples → writes), per-site poller cards, queue depth charts + DLQ badges (replay affordance post-v1), data-tier vitals (PG/VM/Redis/RMQ), SLO burn-down tiles, ingest freshness. Built from the same components as the product — it's also the demo of our own dogfooding.

**Built so far: storage capacity**, as a `Capacity` tab on `/platform` rather than a separate route (`GET /platform/capacity`, permission `platform:read` — an on-call engineer needs this at 3am and it contains no credentials). It answers the question the retention default raises but cannot answer on its own: *will this disk hold two years?*

- **Retention set** against **what the volume sustains**, side by side. That pairing is the page: everything else supports it.
- Disk used/free with a fill bar, and days-until-full at the current rate.
- What is stored: devices, series, samples, measured bytes-per-sample, effective sample interval.
- Growth per day and **per device per year** — the number to plan a fleet with, since storage scales with device count, not elapsed time.
- Warnings in plain language, and only when warranted: disk filling within 30 days, retention exceeding what the volume affords, or nothing written in the last hour (which is what a stalled collection looks like — a failure this project has had twice, presenting as everything healthy).

Every figure is **measured, never derived from configuration**. Bytes-per-sample comes from VictoriaMetrics' own totals; the sample rate from counting what was actually written in the last hour. Deriving the rate from the polling schedule was tried and abandoned: schedules mix 30 s ICMP with 6-hourly inventory sync, so their mean was 5498 s against an effective 65 s — an 85-fold error that would have made every projection on the page wrong.
